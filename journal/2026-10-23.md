## `{hostname}` log path token (0.4.12)
- **Intent:** Several hosts log into one shared NFS/AWS EFS folder (dynatron `vfi-rci-soap-uvicore-api`
  on `pr-vfi-app1`/`app2`, dreml, and others).  The first production night of the RCI service
  produced torn lines in the shared `YYYY-MM-DD_Batch.log`: a line starting `026-10-23...`, a stray
  `2` on its own line, and blank lines.  Give each machine its own file, built into the framework.
- **Changed:**
  - `uvicore/logging/logger.py` `build_file_handler()`: replaces `{hostname}` in the configured
    path with `socket.gethostname()` before `{channel}` handling, so it works for the default log
    and every channel, dated (`DatedFileHandler`) or legacy rotated.  Retention then naturally
    matches only the host's own files.
  - Why it happens: `DatedFileHandler` opens `'a'` (`O_APPEND`).  On one machine the kernel
    serializes appends (and the Linux NFS client serializes them per client), so N processes on one
    host are safe.  NFS has no atomic append ACROSS clients: each computes EOF from its cached
    size, so near-simultaneous writes from two hosts overwrite each other's bytes (torn and lost lines).
  - Tests: `tests/test_logging/test_channels.py`, two new tests (`{hostname}` with and without
    `{channel}`, `socket.gethostname` monkeypatched).  Full suite 634 passed
    (`PYTHONPATH=./tests/apps`, the suite needs it to import app1).
  - Version 0.4.11 -> 0.4.12 (`pyproject.toml`, `uvicore/__init__.py`).
- **Related:** docs `deeper/logging.md` (new "One file per machine" section; corrected "multiple
  processes can share one log" to on-one-machine), `epologue/changelog/0.4.md` §0.4.12,
  `epologue/release-notes.md`; schematic `acme/appstub/config/logger.py` comment.  Not breaking, so
  no upgrade guide.  `mkdocs build --strict` clean.  Not committed or published: the owner pushes to PyPI.
