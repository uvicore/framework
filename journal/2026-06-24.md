# 2026-06-24

## Leaner OpenAPI / Swagger docs (0.4.4)

- **Intent:** A VFI app with the automatic model CRUD API enabled produced a ~235 KB `openapi.json`
  and a sluggish Swagger UI.  Two causes: (1) FastAPI's `separate_input_output_schemas=True` default
  emitted every model twice (`Foo-Input` + `Foo-Output`) even though the pair was byte-identical
  here — ~93% of the doc was `components.schemas` and exactly half of that was the Input/Output
  duplication; (2) Swagger renders the entire standalone **Schemas** section, which is huge once a
  model graph cascades through relations.
- **Changed:**
  - `uvicore/http/package/bootstrap.py` — the api `FastAPI(...)` now passes
    `separate_input_output_schemas=uvicore.config.app.api.openapi.get('separate_schemas', False)`
    (default **False** → one schema per model). Regenerating the VFI app's spec dropped it from
    234 KB / 106 schemas to 127 KB / 58 schemas with no `-Input`/`-Output` suffixes.
  - `uvicore/http/openapi/docs.py` — `get_swagger_ui_html()` gained a `models_expansion: int = -1`
    param rendered as Swagger's `defaultModelsExpandDepth`; bootstrap wires it from
    `openapi.docs.get('models_expansion', -1)`. `-1` hides the Schemas section entirely.
  - Used `.get(..., default)` (not attribute access) for both new keys so existing apps without them
    don't trip the SuperDict missing-key / frozen-config behavior.
- **Tests:** `tests/test_http/test_openapi.py` — swagger `defaultModelsExpandDepth` default+override
  rendering, the `create_http_servers()` wiring (`separate_input_output_schemas is False`), and a
  FastAPI behavior test proving a dual-use model collapses. Note: the live HTTP server tree is never
  built under pytest (`is_http` forced False in `application.py`), and route merging isn't idempotent
  in the session-scoped `app1` fixture, so the test drives `create_http_servers()` directly with a
  dummy truthy `api_routes` rather than walking `uvicore.app.http`. Full suite green (527 passed).
- **Docs:** `docs/http/api/openapi.md` (new "Taming Large Schema Sets" section + config block),
  `epologue/changelog/0.4.md` (0.4.4), `epologue/release-notes.md`. Schematic + this app's
  `config/http.py` stub updated with both keys. Version bumped 0.4.3 → 0.4.4.
- **Related:** The remaining schema bulk is the relation cascade (model `response_model`s embed
  their relations as nested `$ref`s, pulling the whole graph). Not addressed here — relations load
  on-demand via `?include=`, so a future change could stop embedding them in the base schema.
