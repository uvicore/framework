# 2026-07-06

## Rich-powered console logging for uvicore.log (0.4.9)

- **Intent:** Make `uvicore.log`'s console (STDOUT/STDERR) output *much* prettier by rendering it
  with [rich](https://rich.readthedocs.io/) instead of the old `colored`-based `ColoredFormatter`,
  while keeping the public `uvicore.log` interface 100% unchanged and leaving `prettyprinter`
  (`dump()`/`dd()`) and the file handler alone.
- **Dependency:** added `rich==14.2.0` to the **base** `dependencies` in `pyproject.toml` (NOT gated
  behind the `web`/`database`/`redis` extras) so console output is beautiful for every app, CLI
  included.  Regenerated the pinned transitive-subdependency block with
  `poetry run ./list-subdependencies.sh` — this added `markdown-it-py==4.2.0` + `mdurl==0.1.2` and
  dropped the stale `python_version == '3.10'` / `python_full_version < '3.11.3'` conditional pins
  (`async-timeout`, `backports-datetime-fromisoformat`, `exceptiongroup`, `tomli`) that never
  activate under `requires-python >= 3.12`.  Re-locked + reinstalled.
- **What changed** (`uvicore/logging/logger.py`):
  - Removed `ColoredFormatter` (and the `colored` `attr/bg/fg` import, `import re`).  `colored` was
    the logger's *only* consumer, so **removed `colored==2.3.2` from the base deps** entirely
    (verified no remaining imports; the `colorful` subdep is a separate prettyprinter transitive dep
    and stays).  Net dependency footprint is ~a wash (rich + markdown-it-py + mdurl in, colored out).
  - New `RichConsoleHandler(logging.Handler)` owns two lazy rich `Console`s (stdout + stderr, no
    `file=` so pytest capture / stream redirection keeps working).  It keeps the **exact** prefix
    semantics the `Logger` methods emit (`:: header ::`, `## header2 ##`, `=== h3 ===`,
    `---- h4 ----`, `* / - / + / >` items, `NOTICE: `, all-`=`/all-`-` separator/line) and renders
    them via a tweakable `UVICORE_LOG_THEME`:
    - `header()`/`header2()` → full-width `rich.rule.Rule` with a centered title; `header3()`/
      `header4()` → inline styled text.
    - `item()`–`item4()` → colored glyphs `● ◆ ✚ ▸`, indentation preserved.
    - `notice()` → `ℹ NOTICE` badge; `warning()`/`error()` → `⚠`/`✖` prefixes; `critical()` →
      `CRITICAL` badge; `separator()`/`line()` → rules.
  - **Behavior change:** `WARNING`/`ERROR`/`CRITICAL` now emit to **STDERR**; `DEBUG`/`INFO` + all
    layout helpers stay on **STDOUT** (was all-STDOUT).  Confirmed intent with the user.
  - `colors: False` config now falls back to the previous plain, ASCII, STDOUT-only
    `logging.StreamHandler` (no rich, raw prefixes) — an escape hatch for dumb terminals.
  - The `Logger` now stores explicit `self._console_handler` / `self._file_handler` refs (instead of
    relying on `handlers[0]`/`handlers[1]` index order); the `console_handler`/`file_handler`
    contract properties return those.  `dump()`'s file-dump branch silences the real console handler
    object (was a brittle `'logging.StreamHandler' in str(type(handler))` string match that would no
    longer match the rich handler and double-print).
  - Removed a stray leftover `print(exclude)` debug line in the unused `ExcludeFilter`.
- **Idea gleaned** from the side project `dynatron/uvicore/vtcman-uvicore-app/vtcman/console.py`
  (a rich wrapper around `uvicore.log`): the glyph/icon set (`● ◆ ✔ ⊘`, `⚠ ✖ ℹ`) and using
  `console.rule()` for headers.  Adopted the glyphs/icons and full-width rules; **left its
  `progress_steps()` progress-bar helper out of core** (it's beyond the `Logger` contract — possible
  future addition).
- **Tests:** `tests/test_logging/test_logging.py` grew from 2 → 10 tests: console handler is a
  `RichConsoleHandler`, headers/separators render as `Rule`, items carry their glyph + preserve
  indent, notice has a label, STDOUT vs STDERR routing (captured via StringIO consoles), and
  `colors=False` → plain `StreamHandler`.  Note: `uvicore.logging.logger` can't be imported at test
  *collection* time (its `@uvicore.service` decorator resolves config during bootstrap), so imports
  are deferred inside the tests/helpers, and the real `Logger` class is grabbed off the live
  singleton via `type(uvicore.log)` (the decorator replaces the module `Logger` symbol).  Full suite
  green: **557 passed**.
- **Version:** bumped `pyproject.toml` + `uvicore/__init__.py` to **0.4.9**.
- **Docs (sibling `docs` repo):** added the `0.4.9` changelog section (`epologue/changelog/0.4.md`)
  and a release-notes bullet; `mkdocs build --strict` exits 0.  Not committed (per user's commit
  policy).
