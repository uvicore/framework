## Full dependency upgrade for the certifi emSign CA incident (0.4.13)
- **Intent:** The eMudhra emSign CA incident
  (https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576)
  needs `certifi` >= 2026.10.19.  Uvicore pins its whole tree in published metadata, so apps only get
  the fix through a new uvicore release.  Upgraded every dependency to latest while doing it.
- **Changed:**
  - `pyproject.toml`: every top-level, extra and transitive pin bumped to latest (certifi 2026.10.23,
    SQLAlchemy 2.0.51 -> 2.1.6, alembic 1.20.1, FastAPI 0.137.2 -> 0.162.0, Starlette 1.3.1 -> 1.10.0,
    uvicorn 0.54.0, pydantic 2.14.1, cryptography 50.0.2, rich 15.0.0, redis 8.1.0, ...).  The
    transitive block was regenerated with `./list-subdependencies.sh`.  It picked up one new pin,
    `opentelemetry-api==1.45.1 ; extra == 'web'`, which FastAPI 0.162 now requires.  Test-group
    transitives (coverage, pluggy, iniconfig) updated via `poetry update`.  `poetry.lock` re-locked.
  - The one break was SQLAlchemy 2.1: `URL.create()` now percent-encodes `:` in the database part
    (`sqlite+aiosqlite:///%3Amemory%3A`).  It parses back to `:memory:`, so engines are unaffected.
    `tests/test_db/test_dialects.py::test_sqlite` now compares the parsed URL instead of the raw string.
  - Known and left alone: SA 2.1 emits an `SADeprecationWarning` for the `mode=memory` URI in
    `tests/test_db/test_engine_lifecycle.py`.  It still gets the same StaticPool; a future SA release
    will switch it to AsyncAdaptedQueuePool.  Revisit if that test starts to fail.
  - Version 0.4.12 -> 0.4.13 (`pyproject.toml`, `uvicore/__init__.py`).  CLAUDE.md now says SQLAlchemy 2.1.
  - Results: unit suite 634 passed.  `test-db-integration.sh all`: Postgres, MySQL and MariaDB 106
    passed each.
- **Gotcha (SASE VPN / TLS-intercepting proxies):** poetry failed with `CERTIFICATE_VERIFY_FAILED:
  self-signed certificate in certificate chain` because it verifies with certifi, not the system
  store.  The fix is to keep verification on and point poetry at the system bundle:
  `POETRY_CERTIFICATES_PYPI_CERT=/etc/ssl/certs/ca-certificates.crt`.  A headless keyring error
  ("Item does not exist") during install was fixed with
  `PYTHON_KEYRING_BACKEND=keyring.backends.null.Keyring`.  Avoid `--trusted-host`/`UV_TRUSTED_HOST`
  for pypi.org: they turn certificate verification off, which defeats the point of a CA-trust fix.
- **Related:** docs `epologue/changelog/0.4.md` §0.4.13 and `epologue/release-notes.md`; schematic
  `pyproject.toml` pytest-asyncio 1.4.1.  Not breaking, so no upgrade guide and no ADR.  Not committed
  or published.
