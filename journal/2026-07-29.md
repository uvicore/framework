# 2026-07-29

## Date-stamped log filenames and named log channels (0.4.10)

- **Intent:** Three related asks about `uvicore.log`, driven by long-running consumer workloads and
  by apps whose features each want their own log:
  1. rotation is unreliable for a process that loops forever;
  2. prefer the date built into the filename (`2026-07-29_Processor.log`), rolling to the next day's
     file on its own;
  3. one app needs *many* logs — `Auditor`, `Importer`, `Processor`, `RulesEngine`, `Transformer`.

- **First, the adjudication.** Read the real CPython 3.12/3.14 `logging/handlers.py` before designing,
  because the stated premise is half wrong and building on it would have produced the wrong design.
  "A long-running loop never rotates" is **false** — `BaseRotatingHandler.emit` checks
  `shouldRollover` on *every* record, before the write. The real failures:
  - **Multi-process = silent permanent data loss.** With `uvicorn --workers N` (or a CLI command
    sharing `LOG_FILE_PATH`), processes race on `os.rename`. The loser's `doRollover` hits
    `if os.path.exists(dfn): return` — returning *without updating `self.rolloverAt`*. That process
    then `shouldRollover() == True` forever (a stat syscall per log line), **never rotates again**,
    and keeps appending to a renamed or `backupCount`-unlinked inode until it dies. `backupCount` can
    also `os.remove` a file a peer still holds open.
  - **Archives named for the wrong day.** `doRollover` names from `rolloverAt - interval` then
    recomputes `rolloverAt` from *now*, so a process idle Mon→Thu emits one archive named for Monday
    containing four days of records and *no files at all* for Tue/Wed.

  Date-in-filename fixes all of it — because nothing is ever renamed — which is the honest
  justification for the change.

- **Changed — `uvicore/logging/handlers.py` (new, stdlib-only, no uvicore imports so it is unit
  testable without a bootstrap):** `DatedFileHandler(logging.FileHandler)`.
  - Hooked in **`emit`**, deliberately *not* `_open` — `_open` runs once per stream lifetime, so the
    common "compute the filename in `_open`" implementation would look fine in a two-record unit test
    and then never roll in the process this exists for.
  - Filename derived from **`record.created`**, not `time.time()`, because `Formatter.formatTime`
    renders `%(asctime)s` from `record.created`. That is what preserves the invariant that makes dated
    files worth having: every timestamp inside `2026-07-29_X.log` starts with `2026-07-29`. Rolling is
    forward-only; per-record bucketing was rejected (a stepping clock could thrash open/close).
  - Two int compares per record; `strftime` at most once per wall-clock second, never for a static
    path. `makedirs(exist_ok=True)` on *every* resolve (dated dirs, and operators deleting the dir
    under a live process) — the framework previously created no directories at all, so a bad
    `LOG_FILE_PATH` raised mid-bootstrap.
  - `_reopen` takes only the handler's own RLock — never module-level `logging._lock`, which
    deadlocks AB-BA against `FileHandler.close()` (that takes `self.lock` then `_lock`).
  - **`retention` (days, default 0)** replaces `backupCount`, which *cannot* work with dated names:
    `getFilesToDelete` builds its prefix from *today's* `baseFilename`, so yesterday's files never
    match and pruning silently stops. Without this the change would have swapped a rotation bug for
    unbounded disk growth. Swept on roll (~daily), never per record, against a glob derived from the
    handler's own pattern so one channel can never prune another's files.

- **Changed — `uvicore/logging/logger.py`:**
  - `DEFAULT_CONFIG` + `CHANNEL_INHERIT_RESET` module constants; the manual two-level dict splat
    replaced with `Dict(config).clone().defaults(DEFAULT_CONFIG)`. **`.clone()` is load-bearing, not
    style** — `Dict` holds nested SuperDicts by reference and `defaults()` mutates in place, so
    without it constructing a `Logger` rewrites the live `uvicore.config.app.logger`. The old splat
    avoided this by accident (it built fresh plain dicts). Covered by a regression test.
  - Extracted `build_console_handler()` / `build_file_handler()`. The latter selects
    `DatedFileHandler` when the path has strftime tokens and `TimedRotatingFileHandler` when it does
    not — that auto-detection is what makes the whole change backward compatible with **zero**
    migration. `{channel}` substituted with `.replace()`, not `.format()` (a real log path can
    contain other braces).
  - Extracted a `LogWriter` base holding all 20 emit/layout methods, `__call__` and `dump()`, shared
    by `Logger` and the new `Channel`. `dump()` needed exactly one line changed —
    `self._name or 'root'` → `self.logger.name` — which is behavior-identical for the root logger
    (`logging.getLogger().name` *is* `'root'`) and generalizes to channels for free. Also hardened its
    two `self.<x>_handler.level` dereferences, which were guarded only by the config `enabled` flag.
  - New `Channel(LogWriter, LogChannelInterface)`: own named python logger, own console+file pair,
    **`propagate = False`**.
  - `Logger.channel(name)` / `.channels` — lazy + cached like `cache/manager.py`'s
    `connect()`/`_backends`, reading `uvicore.config('app.logger.channels')` **live** so a channel
    added after bootstrap (e.g. from a provider `boot()`) still works.
  - `name()`'s one-shot scope moved from a singleton attribute to a **`ContextVar`**. It was a real
    async bug: `uvicore.log` is a singleton, so two concurrent tasks — or two of FastAPI's `anyio`
    worker threads running sync endpoints — could clobber the scope between `name()` and the emit,
    misattributing lines and therefore misapplying `filters`/`exclude`. With per-channel *files* the
    same class of bug would have written lines into the wrong file. No API change.
  - Deleted the unused `ExcludeFilter`; added an explicit `import logging.handlers` (line 305
    previously called it, working only transitively via `import logging.config`).

- **Why `propagate = False` (the one genuinely subtle decision).** The default channel's file handler
  lives on the **root** logger, and `Logger.callHandlers` walks the hierarchy firing *every* ancestor
  handler with no way to address them individually — so `propagate = True` writes every channel line
  into the default log file as well. The alternative (a rejecting filter on the root file handler
  holding a channel registry) is order-sensitive with lazy channels, formats-then-discards every
  channel record, and breaks the moment a channel wants its own console level. Rejected. Trade-off
  accepted and documented: channel records don't reach root handlers (`caplog`, Sentry) — attach to
  `logging.getLogger('<channel>')` instead.

- **Footgun caught late, via the ship-checklist's "make app1 exercise it" item.** app1's log path is
  static `/tmp/app1.log` with no `{channel}` token, which meant every channel *and* the default log
  collapsed into one shared file — silently defeating the entire feature for anyone who adds channels
  without also adding the token. Fixed in `build_file_handler()`: when the path has no `{channel}`
  token and this is a named channel, the channel name is appended before the extension
  (`app1.log` → `app1_Processor.log`). A channel now always gets its own file, which is its whole
  reason to exist. This also gave app1 real end-to-end coverage of a channel riding on the *legacy*
  `TimedRotatingFileHandler`, not just the dated one.

- **Other decisions worth the record:** channels live in app config only (logging registers before any
  package config merges); channels inherit `console`/`file` but **not** `filters`/`exclude` (those
  prefix-match framework logger names, so inheriting an include-style filter would leave every channel
  file silently empty); channel names **may not contain a dot** (a channel named `uvicore` would become
  the *parent* of `uvicore.orm` and vacuum every ORM record into its file — raises); unknown channels
  auto-create rather than raise; and the default file handler **stays on root** so third-party records
  that propagate up (`sqlalchemy`, `aiosqlite`, `asyncpg`, `asyncio`, `httpx`) keep landing where the
  shipped `exclude` lists filter them.

- **Deleted `uvicore/factories/`** entirely — its only member was a `Logger` factory never wired as an
  IoC `factory=`. Verified zero references framework-wide.

- **Tests: 11 → 53 in `tests/test_logging/`** (full suite 558 → 600, all passing). There was previously
  **zero** coverage of the file handler. New `test_handlers.py` (15 pure-unit, no fixture) and
  `test_channels.py` (18, app1 fixture) plus 12 additions to `test_logging.py`. Two hygiene helpers
  were needed because `logging.getLogger()` and `logging.Logger.manager.loggerDict` are process-wide
  and never shrink: an `isolated_logger()` contextmanager that restores `root.handlers`/`level` and
  closes what it added, and channel teardown that strips channel logger handlers. Without them ad-hoc
  `Logger` construction leaks handlers into every later test and writes each line N times. Note two of
  my first-draft handler tests were wrong — they counted `time.strftime` calls globally and so caught
  `Formatter.formatTime`'s calls for `%(asctime)s` too; now filtered to the handler's own pattern.

- **Verified end-to-end** against app1: five dated per-channel files created with correct contents and
  correct `%(name)s` column, no cross-contamination with the default log, console rendering (rules,
  glyphs, NOTICE badge) unchanged, day-roll producing a second file with the first untouched and no
  `*.log.<date>` archives anywhere, and a static path still yielding a `TimedRotatingFileHandler`.
  `bin/black-check.sh` cannot run — `black` is neither installed nor declared in `pyproject.toml`, and
  the codebase is not black-formatted (single quotes, `if x: return y` one-liners); new code matches
  surrounding house style instead.
