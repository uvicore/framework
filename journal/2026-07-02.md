# 2026-07-02

## Fix view-composer dict-form registration + clean up composer stubs/generator (0.4.7)

- **Intent:** While documenting view composers in the docs repo, discovered the composer
  scaffolding still referenced the removed pre-0.4 `self.composers()` / `self.views()` provider
  helpers, and that the **dict form** of `register_http_view_composers()` was actually broken.
- **Bug fixed:** `uvicore/http/package/registers.py` — the `dict` branch of
  `register_http_view_composers()` called a non-existent `self.composers(mod, views)` and raised
  `AttributeError` on boot for anyone registering multiple composers via a dict.  Now recurses into
  `self.register_http_view_composers(mod, views)`.  (The single string/list form always worked.)
- **Scaffold/CLI cleanup (stale pre-0.4 API):**
  - `uvicore/http/commands/stubs/composer.py` — example comment now uses
    `register_http_view_composers(...)` instead of `self.composer(...)`.
  - `uvicore/http/commands/generators.py` — the `gen composer` "add this to your provider" hint now
    prints `self.register_http_view_composers('<module>', '<short_name>/*')` with the **correct**
    method name and argument order (was `self.composers('<short_name>/*', '<module>')`).
  - `tests/apps/app1/package/provider.py` — stale `self.composers()` comment reworded; the dict-form
    example de-duplicated (was the same key twice) and is now **active** so every app1 boot exercises
    the fixed dict-form path.
- **Tests:** new `tests/test_http/test_view_composers.py` (5 tests) — dict-form registration lands
  in `package.web.view_composers`, `@uvicore.composer()` IoC binding, aggregation into
  `uvicore.config.uvicore.http.view_composers`, end-to-end merge via `response.View()`, and that a
  controller-set context key wins over the composer (`.defaults()` merge).  Added
  `tests/test_http/conftest.py` `webserver` fixture (mirrors the api harness — rebuilds the HTTP
  server under pytest so templates + composer config are wired, no-op if already built) and app1
  composer/view fixtures (`http/composers/layout.py`, `http/composers/sidebar.py`,
  `http/views/app1/composed.j2`).  Full suite green: **540 passed**.
- **Version:** bumped `pyproject.toml` + `uvicore/__init__.py` to **0.4.7** (0.4.6 already shipped).
- **Docs (sibling `docs` repo):** new `http/web/view-composers.md`, wired into nav + web index,
  fixed the dead composer link in `web/templating.md`, and added the 0.4.7 changelog +
  release-notes entries.  Not committed (per user's commit policy).
